How channels coexist without corrupting the graph
All four channels can run simultaneously — but they write to the graph through the same node resolution layer, which serializes writes on a per-node basis. Two channels discovering the same node at the same time results in a merge, not a race condition.
Node-level write locks. When any channel begins writing to a node, that node is locked for ~200ms. Other channels queue their write. The second write is always treated as a merge candidate, not an overwrite — so the slower channel still contributes its observation.
Source hierarchy on simultaneous conflict. If Exploration and Document ingestion both write to the same node in the same lock window with conflicting values — Document wins (weight 72 > 60), Exploration's version is stored as a conflict record and surfaced for review.
Human input always pauses Exploration. When a human types a direct instruction, the Exploration agent pauses its current action and finishes its pending write before the human input is processed. This prevents the human's high-confidence write from being immediately contradicted by an in-flight Playwright observation.
Schema ingestion runs in isolation first. API/schema ingestion (Channel 4) runs a dry-run pass before writing — it computes what it would write, checks for conflicts with existing nodes, and only then commits. This prevents a large schema import from flooding the conflict queue.
Document ingestion directs Exploration. This is the key cross-channel interaction. When Document ingestion extracts a requirement ("users must verify email before accessing premium features"), it doesn't just write a rule node — it also pushes a high-priority task onto the Exploration frontier: "verify this rule is implemented." The two channels actively collaborate.

Priority score formula — every frontier item gets scored, highest runs next

priority = (gap_weight × 0.4) + (confidence_deficit × 0.3) + (doc_intent × 0.2) + (recency_penalty × 0.1)

gap_weight: How critical is this unknown? Auth gaps score 100, payment gaps 90, UI cosmetics 20.
confidence_deficit: (100 − current_confidence). A node at 40% scores 60 here; one at 95% scores 5.
doc_intent: Was this task created by Document ingestion? If a spec mentioned something unexplored, it scores higher than pure curiosity-driven exploration.
recency_penalty: If this path was explored recently, score decreases. Avoids revisiting the same territory in a loop.

Two exploration phases — the scheduler shifts between them based on coverage metrics
Phase 1 — Breadth (0–60% structural coverage)
Frontier prioritizes undiscovered pages and primary flows. Goal: build the map. Doc-intent items run alongside but don't dominate. Human inputs always jump queue.
Phase 2 — Depth (60%+ structural coverage)
Frontier shifts to low-confidence nodes, untested edge cases, conflict resolution, and doc-intent items. Map is known — now understand what's on it. Boundary testing, error states, conditional flows.
The loop that never stops
Training isn't a phase that ends before working begins. Once an Intellion reaches ~60% coverage on the structural layer, it can start working. But the frontier scheduler keeps running — in parallel with missions. Every mission the Intellion executes feeds new observations back into the knowledge graph, which updates confidence scores, closes gaps, and adds new items to the frontier. Working is just training with a specific task attached.
